1. 计算机操作系统

如果现在提起计算机操作系统，可能多数人的第一反应就是大名鼎鼎的 Windows，此外有些人可能也接触过 macOS 或者 Linux 的各类发行版（如：Ubuntu, Fedora, Manjaro, CentOS 等），它们都是计算机操作系统。

操作系统简史

  • 最初：计算机体积庞大，性能有限，多为特定目的服务，因此无需完整的操作系统。
  • 发展：随着计算机性能的提升和功能需求的日益复杂，操作系统开始成型，最初是为了帮助用户进行 批处理操作。
  • 现代：操作系统逐渐形成庞大体系，成为联络一般用户和计算机底层设备的中介，让用户无需关心绝大多数底层设备，大大降低了使用学习成本。

现代操作系统的核心功能

现代个人计算机操作系统功能复杂，但总体来说，一直是用户与底层硬件交流的桥梁。

  • 进程管理：协调多个程序（进程）并发执行，确保CPU资源的合理分配。
  • 内存管理：合理分配和回收计算机有限的内存资源。
  • 文件系统：建立数据结构来存储和管理计算机上的文件。
  • 网络通信：实现与互联网上其他计算机的有效联络。
  • 安全机制：保护数据不被未授权访问，以及免受病毒攻击。
  • 用户界面：提供图形化用户界面，方便用户与计算机交互。
  • 驱动程序：管理与硬件直接交互的软件，发挥硬件功能。

2. 进程与线程：程序在电脑里的“生命”

简单而不太严谨地来说，进程就是已被载入的程序：当我们启动一个程序的时候，操作系统会从硬盘中读取程序文件，将程序内容加载入内存中，之后CPU就会执行这个程序。

线程：进程中的“执行单元”

如果说进程是操作系统分配资源的基本单位（好比一座工厂），那么线程就是CPU调度的基本单位（工厂里的生产线）。一个进程可以包含一个或多个线程，它们共享进程的内存空间和资源，但每个线程有自己独立的执行栈和程序计数器。

  • 资源共享：同一进程内的所有线程共享该进程的地址空间、全局变量和打开的文件，这使得线程间通信比进程间通信更高效、简单。
  • 轻量级：创建和切换线程的开销远小于进程，因此可以更高效地实现并发。
  • 并发执行：在多核CPU上，多线程可以真正地并行执行，从而显著提高程序性能。在单核CPU上，通过快速的线程切换，也能实现并发的“假象”。
  • 应用场景：
    • Web服务器使用多线程来同时处理多个客户端的请求。
    • 图形用户界面（GUI）程序使用一个线程负责界面响应，另一个线程执行耗时操作，避免界面卡顿。
    • 大型计算任务可以分解为多个子任务，交由多个线程并行处理。

进程与线程的核心区别

特性 进程 线程
基本单位 资源分配的基本单位 CPU调度的基本单位
资源开销 创建和销毁开销大 创建和销毁开销小（轻量级）
内存空间 拥有独立的内存地址空间 共享所属进程的内存空间
通信方式 复杂，需专门的IPC机制（如管道、套接字） 简单，可直接读写共享数据（需注意同步）
健壮性 一个进程崩溃不影响其他进程 一个线程崩溃会导致整个进程崩溃

查看当前运行的进程

  • htop：一个交互式工具，可以方便地查看当前运行的所有进程，以及系统CPU、内存占用情况。
    • 使用鼠标或F1-F10功能键操作，例如F3 (Search)、F4 (Filter)、F5 (Tree/List)。
    • [建议安装并运行 sudo apt install htop 来即时查看。]
  • ps (process status)：常用的输出进程状态的命令行工具。
    • 直接调用 ps 仅显示当前终端的相关进程。
    • ps aux：显示所有进程。

进程标识符（PID）

PID (Process Identifier) 是一个数字，是进程的唯一标识。当用户想挂起、继续或终止进程时，可以使用PID作为索引。

进程优先级与状态

为了让多个程序看起来“同时”执行，操作系统需要快速地在进程之间切换计算资源，这引入了进程优先级和进程状态的概念。

  • 优先级与nice值：
    • nice值越高，代表一个进程对其他进程越“nice”（友好），对应的优先级也就越低。范围从-20（高优先级）到19（低优先级）。
    • 可以使用 nice -n 10 vim 在运行时指定优先级，或 renice -n 10 -p 12345 重新指定优先级。
  • 进程状态：
    • R (Running)：正在运行/可以立刻运行（包含就绪态）。
    • S (Sleeping)：可被中断的睡眠状态，等待资源。
    • D (Disk Sleep)：不可被中断的睡眠状态，通常阻塞在磁盘I/O上。
    • T (Traced/Stopped)：被跟踪（调试中）或被挂起（如Ctrl + Z）。
    • Z (Zombie)：僵尸进程，进程已结束但仍占用PID，等待父进程回收。

用户进程控制

图：信号处理机制示意图

  • 信号：Unix系统中进程间通信最古老的方式之一。
    • kill -l：显示所有信号名称。
    • SIGTERM (15)：标准的终止进程信号，程序可捕获并优雅退出。
    • SIGKILL (9)：强制终止信号，无法被捕获或忽略。
  • 管道 (Pipe)：用于有亲缘关系的进程（如父子进程）之间单向通信。例如 ls -l | grep ".txt"，`ls`的输出通过管道成为了`grep`的输入。
  • 套接字 (Socket)：更通用的通信机制，不仅可用于同一台机器上的进程间通信，还可用于网络上不同机器间的进程通信。

用户进程控制

  • 发送信号：使用 kill 命令向进程发送信号。在htop中按K键也可以方便地发送信号。
  • 前后台切换：
    • 在命令末尾加 &：将命令放到后台运行 (./matmul &)。
    • 按 Ctrl + Z：发送 SIGTSTP 信号，使前台进程挂起。
    • jobs：查看当前shell中挂起或后台运行的进程。
    • fg %N：将代号为N的后台进程切换到前台。
    • bg %N：将代号为N的挂起进程切换到后台继续运行。
  • 脱离终端：
    • nohup：nohup command &，使程序运行不受SIGHUP（终端关闭信号）影响，输出默认重定向到nohup.out。
    • tmux：一个命令行多终端复用工具，解决SSH断开后程序停止的问题。详情可参考官方Wiki。
      • 会话 (session), 窗口 (window), 面板 (pane)：tmux的组织结构。
      • tmux：启动一个新的tmux会话。
      • Ctrl + B 是tmux的全局前缀命令。
      • 快捷键示例：Ctrl+B % (左右分屏), Ctrl+B " (上下分屏), Ctrl+B d (脱离会话), Ctrl+B c (新建窗口)。
      • tmux attach [-t session_name]：重新连接到会话。

内存管理基础

操作系统的内存管理是保证程序正常运行的重要机制。现代操作系统引入了虚拟内存的概念，让每个进程都认为自己拥有独立的完整内存空间。

  • 虚拟内存：每个进程有自己的虚拟地址空间，操作系统将虚拟地址映射到实际的物理内存。这样既隔离了不同进程的内存，又使得程序可以使用比实际物理内存更大的地址空间。
  • 栈 (Stack)：用于存储函数调用的局部变量、返回地址等。栈的特点是后进先出（LIFO），当函数返回时，其局部变量会自动释放。
  • 堆 (Heap)：用于动态分配内存。程序在运行时可以根据需要在堆上申请和释放内存，但需要程序员手动管理（在C/C++中）或依赖垃圾回收机制（在Java、Python中）。
  • 代码段与数据段：代码段存储程序的机器指令，数据段存储全局变量和静态变量。

3. 服务与例行任务：幕后英雄与时间管理

服务（Daemon）

服务的特征意味着服务进程必须独立于用户的登录，不能随用户的退出而被终止。这类一直默默工作于后台的进程被称为守护进程 (daemon)。

  • 服务管理：目前绝大多数Linux发行版的init方案是systemd，其管理系统服务的命令是systemctl。
    • systemctl status：一览系统服务运行情况。
    • systemctl start/stop/restart/reload [unit]：开启/关闭/重启/重载服务。
    • systemctl enable/disable [unit]：设置/取消服务开机自启。
    • systemctl daemon-reload：重载systemd配置，在创建或修改服务文件后执行。
  • 自定义服务：可以通过编写一个简单的.service文件将其注册为systemd服务，通常存放在/etc/systemd/system/目录下。

例行性任务

指基于时间的一次或多次周期性定时任务。在Linux中，主要通过at和crontab实现。

  • at 命令：负责单次计划任务。
    • at now + 1min：一分钟后执行命令，命令从标准输入读取，或用 at -f script.sh now。
    • at -l：列出任务；at -r <编号>：删除任务。
    • 注意：at默认将标准输出和标准错误以邮件形式发送给用户。
  • crontab 命令：负责周期性任务设置。
    • crontab -e：编辑当前用户的定时任务配置文件。
    • 配置格式：每一行代表一个任务，前半段为时间，后半段为shell执行命令。 
      # 分   时   日   月   星期  | 命令
* * * * * echo "hello" >> ~/count # 每分钟输出 hello 到家目录下 count 文件
    • 可以通过 https://crontab.guru/ 网站解析时间字段。

4. Shell与环境变量：你的命令行“魔法棒”

什么是Shell

Shell 是Linux的命令解释程序，是用户和内核之间的接口。除了作为命令解释程序外，Shell同时还提供了一个可支持强大脚本语言的程序环境。

  • Bash (Bourne Again Shell)：大部分Linux系统的默认Shell，是Bourne Shell的扩展。可以参考高级Bash脚本指南深入学习。
    • 定制环境：通过修改.bash_profile、.bashrc等文件配置环境变量。
    • 别名 (alias)：用短命令代替长命令（alias ll='ls -alF'）。
      • alias：查看目前存在的别名。
      • type [命令]：检查命令是否被alias。

Bash脚本的运行

  • 在指定的Shell下执行：bash script.sh。
  • 设置为可执行后直接运行：chmod a+x script.sh 后 ./script.sh。
  • `.` 或 `source` 命令：在当前shell中执行脚本，脚本中的变量赋值、函数定义、目录切换等变化都会在当前shell中生效（如激活Python虚拟环境：. venv/bin/activate）。
  • Shebang (#!)：脚本文件首行的#!/bin/bash指定了该脚本的解释器。
  • 命令行多命令操作：
    • ;：按顺序执行。
    • &&：前一个成功才执行后一个。
    • ||：前一个失败才执行后一个。
    • &：后台方式执行命令。

Shell变量

Shell支持在程序中使用变量，但它将任何变量值都当作字符串。

  • 用户自定义变量：name=value (等号两边不允许有空格)。引用时使用$name或${name}。
  • 环境变量：系统为每个用户建立的默认工作环境，由一组环境变量定义。
    • HOME：用户主目录。
    • LOGNAME：登录用户名。
    • PATH：命令搜索路径，路径以冒号分割。
    • PWD：用户当前工作目录路径。
    • export A=1：定义环境变量，在当前shell及其子进程中有效。
    • env：列出所有已定义的环境变量。
  • 位置变量：$0（程序名），$1, $2, ...（参数）。
  • 特殊变量：
    • $#：命令行上的参数个数。
    • $?：最后命令的退出代码（0表示成功）。
    • $$：当前进程的PID。
    • $*：命令行所有参数构成的一个字符串。

变量输入与输出

  • 输入：read 命令读取用户输入，并将内容赋值给变量。
    • read -p "Enter your name: " name
    • 建议加上-r参数，避免反斜杠被视为转义符。
  • 输出：echo 和 printf 命令。
    • echo：输出变量信息。-n不输出换行，-e解析转义字符（如\n）。
    • printf：类似于C语言中的printf()函数，支持格式化输出。

文件权限管理

Linux系统中的每个文件和目录都有特定的权限设置，决定了谁可以对其进行什么操作。

  • 三种权限类型：
    • 读 (r)：可以查看文件内容或列出目录内容
    • 写 (w)：可以修改文件内容或在目录中创建/删除文件
    • 执行 (x)：可以运行文件（如果是程序）或进入目录
  • 三种用户类型：
    • 用户 (u)：文件的所有者
    • 组 (g)：文件所属的用户组
    • 其他 (o)：系统中的其他用户
  • 权限表示：如 -rwxr-xr--，第一位是文件类型（-表示文件，d表示目录），后面每三位分别表示用户、组、其他的权限。
  • 修改权限：使用 chmod 命令。
    • chmod 755 file：设置文件权限为rwxr-xr-x
    • chmod +x script.sh：给文件添加执行权限
    • chmod u+w,g-r file：给用户添加写权限，移除组的读权限

5. 思考题

  • Ctrl + C：尝试描述在终端运行程序时，用户按下 Ctrl + C 后发生的事情。
  • SIGKILL (kill -9) 可以杀死所有进程吗？
    • 状态为 D (Disk sleep) 与 Z (Zombie) 的进程收到 SIGKILL 信号后会发生什么？
    • 可以向 1号进程 init 发送 SIGKILL 信号吗？发送之后会发生什么？
  • nohup 合适吗？ 某同学使用 Python 写了一个小网站，他准备登录服务器后用 nohup 来运行他的网站。尝试指出这么做可能的问题。
  • 多人使用的 tmux：在实验室的机器中，可能出现多个人同时使用同一个 Linux 账号的场景。此时如果这几个人同时使用 tmux 的话，会出现互相影响的情况。请给出一种解决方案。
  • 服务日志：给出使用 systemd 相关工具输出以下内容的命令：
    • 某个服务的日志
    • 某个正在运行的服务正在输出的日志
    • 系统正在输出的日志
    • 上一次启动到关机的所有日志
  • 耗时的定时任务：如果一个定时任务的执行时间超过了 crontab 中两次任务执行的时间间隔，会发生什么事情？如果用 systemd timer，能否避免这个问题？
